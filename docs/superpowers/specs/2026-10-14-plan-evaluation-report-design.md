# Plan evaluation, review artifacts, and artwork handoff

Status: proposed written design for user review. The conversational design and
visual direction are approved; product implementation is not yet approved.

## Purpose

Enable an image-capable agent to turn a generated raster into faithful editable
SVG through an inspect → declare → execute → compare → accept/reject loop.
Users receive a clean artwork handoff and can enter Review / Edit for detail.
The same evidence must support agent scripts and interactive inspection.

Success means faithful shape and paint with justified geometric complexity,
not simply successful tool execution, fewer commands, or byte identity with a
reference SVG. Shape and fill have independent evaluation and acceptance.

## Scope and boundaries

This design covers review artifacts, trial records, headless orchestration,
the user-facing report and its inspector. It does not change fitting algorithms,
plan semantics, geometry ownership, or paint resolution. Those remain engine
concerns. The peer's replay correction is a prerequisite for completing the
empirical radish loop, not part of this report implementation.

Do not remove the MCP UI or require scripts in every host. Use one typed engine
contract and one artifact-generation path. Scripts orchestrate that contract;
the report and optional MCP UI present its artifacts. Neither may reimplement
corner detection, fitting, fill resolution or plan validation.

## Review sequence

1. Trace once and save the baseline plus source evidence and resolved settings.
2. Review the whole drawing independently for shape and fill.
3. Identify suspect regions and request focused crops, rather than generating
   every possible region panel for every trial.
4. Record a specific hypothesis and exact version-addressed plan. Correct
   corner declarations before broad side refits when corner evidence is wrong.
5. Execute against the chosen retained parent; preserve the request and outcome
   even when no candidate is published.
6. Review the candidate against source, baseline and parent. Accept explicitly,
   reject and branch from a better version, or record a blocker.
7. Deliver the accepted SVG and associated review history. No accepted version
   means an explicitly provisional handoff, not a fabricated completion state.

An agent can make explicit review decisions under the user's task authority;
the workflow does not require a human click for every trial. Record who made
each decision and why. Human review uses the same artifacts.

## Independent evaluation tracks

### Shape

Use neutral, consistent paint to inspect silhouettes, individual region
boundaries, holes, seams, corners, curves, primitives, symmetry and clones.
Keep adjacent regions distinguishable and expose overlaps; do not visually
union them merely to create a monochrome presentation.

Show the source raster alongside retained source polylines. These polylines are
trace evidence, not authoritative intended geometry. Clean parent/candidate
views judge shape without annotation clutter. Annotated views provide the
addresses required to write plans.

Report per-region L/Q/C/A counts, total drawable commands excluding move,
corner counts and kinds, other stored features, topology changes and available
geometric residuals. Distinguish corner-owned from free commands. Label missing
diagnostics or explicitly derived values; absence is not zero.

### Fill

Hold geometry, viewport and sampling support fixed when comparing paint.
Compare source color with flat/gradient assignments, palette and interior
residuals. Treat antialiasing at the boundary separately from interior paint.
If an edit changes geometry, re-evaluate fill on the resulting geometry but do
not attribute changed coverage as a fill-only improvement.

The original raster remains source evidence in both tracks. A final full-color
composite is a sanity check, not a combined quality score or substitute for
independent shape/fill decisions. Background/cutout export settings and their
visible topology effects must be recorded, not hidden inside a color score.

## Comparison and annotation artifacts

Every selected comparison has identical framing and scale across versions.
The reusable comparison bundle contains:

- Clean source/parent/candidate images; baseline accessible as a separate
  comparison reference. Source-polylines view available in the shape track.
- Mandatory annotated SVG and raster map views, not optional decoration.
- Machine-readable IDs, source correspondence, editability and diagnostics.
- Explicit viewport, track, selected IDs and overlay configuration so the same
  view can be regenerated by a script without operating UI controls.

Failed executions have no candidate view. Reference the parent and actual error
instead of synthesizing an after-image.

Overlay layers are regions, paths including cutouts, commands, stored features,
and source correspondence. Features distinguish point corners from rounded
entry/exit spans, plus stored inflections and junctions. The renderer must not
redetect features and create a competing interpretation.

Whole-drawing default: region labels. Selecting a region enables its commands
and features. Selection highlights geometry and exposes exact plan addresses
and metadata; selection alone never edits the drawing. Use color-coded segments
and legends without leader lines. Provide readable IDs in focused views.

Synchronize selection, crop, pan and zoom across comparison views. Use retained
lineage, not equal command indices, to find counterparts across versions.
Represent one-to-many and many-to-one correspondence explicitly. Show unmapped
or ambiguous states rather than guessing; unavailable mappings cannot become
editable addresses through UI inference.

## Trial record and acceptance

The trial record is review metadata linked to immutable engine versions, not a
second authoritative drawing. It contains:

| Field group | Required information |
| --- | --- |
| Identity | Run/trial ID, source hash, build identity, schema identity, timestamps |
| Request | Drawing/base version, hypothesis, target scope, exact submitted plan, resolved settings |
| Execution | Pending/succeeded/failed, elapsed time, published candidate or null, classified error |
| Evidence | Artifact references and hashes, viewport/layers, region diagnostics and correspondence |
| Review | Independent shape and fill verdicts, reasons, reviewer and evidence references |
| Disposition | Proposed/accepted/rejected/blocked, reason and branch ancestry |

Shape/fill verdicts are pass, fail or not-evaluated. Execution success never
implies a pass. An unchanged track may reuse a prior verdict only when the
relevant inputs are proven unchanged; record the reused evidence explicitly.

The run has an explicit accepted-version pointer, initially null. Promotion is
an explicit review action and requires both tracks to pass for that version.
Do not combine accepted geometry from one version with paint from another
outside an engine plan. Rejected candidates remain inspectable and do not
replace the accepted result. A blocked trial can coexist with an earlier
accepted result and must not invalidate it silently.

Classify schema/address errors, fit-guard rejection, replay/provenance failure,
transport failure and artifact retrieval failure separately. Preserve raw errors
and partial artifacts. Do not automatically retrace or loosen tolerances to
conceal a failure. If execution outcome is unknown, reconcile versions before
retrying a potentially mutating request.

## User-facing handoff

Default to a finished-artwork handoff, not an inspector dashboard:

- Large clean accepted SVG preview and primary Download SVG action.
- Concise summary of changes, remaining limitations and truthful status:
  accepted, needs review or incomplete.
- Compare with original, with synchronized views and separate Shape/Fill modes.
- Review / Edit entry point to detailed inspection and plan-driven candidates.

If nothing is accepted, label the baseline provisional and its download
accordingly. The latest experiment must never silently replace the handoff.
Review / Edit exposes regions, overlay toggles, selection metadata, independent
diagnostics and trial cards. Plans/settings/evidence are downloadable details,
not default visual clutter. No direct coordinate-editing tool is introduced.

Use the approved radish mockup as layout reference:
`.superpowers/brainstorm/30393-1791997367/content/radish-handoff-inspector.html`.
It is a throwaway prototype, not production implementation. Its orange-focused
viewport, unavailable correspondence, limited comparisons and in-page controls
must not be mistaken for implemented generalized capabilities.

## Packaging, delivery and lifecycle

The engine/service owns source evidence, plans, replay and immutable versions.
Shared artifact generation owns maps, images, crops and diagnostics. Skill
scripts own schema discovery, trial orchestration and persistent run bundles.
The report and optional MCP widget are viewers of those bundles.

Use linked SVG/PNG/JSON files and a manifest rather than repeating every large
panel in every tool response. Provide overview first and focused artifacts on
demand. Artifact-only requests must not instantiate additional widgets. Download
must deliver actual file contents, not only a drawing URI.

Local scripts are sufficient for orchestration where execution and image
inspection are available. Remote ChatGPT/mobile hosts may lack those abilities;
retain MCP access and verify host-specific display/download behavior. No blanket
claim that packaged skills replace the UI is made.

Saved bundles remain inspectable after server restart. A live drawing handle
does not. Exported plans alone are not a session backup: resumable import and
ID rebinding are a separate contract outside this scope. If a handle expires,
mark it expired and keep the historical evidence; a new trace is a new run.

## Validation and completion

Validate through existing checks and temporary fixtures; no new permanent tests
are required by this design, consistent with the user's instruction.

Before calling the workflow proven:

- Complete radish trace, bounded plan, published child, separate reviews,
  explicit acceptance/rejection and exact SVG export using the real service.
- Repeat on a geometric logo and a compound/cutout case.
- Verify command/feature IDs, rounded spans, one-to-many and unmapped cases,
  fixed crop/scale, and headless/interactive artifact equivalence.
- Exercise failed plans, unavailable diagnostics, missing artifacts, expired
  handles and unknown execution outcomes without false completion states.
- Check basic keyboard access, heading hierarchy, readable labels/contrast,
  downloads, and that selection causes no mutation.

Distill the packaged eval-loop skill from these recorded executions, including
rejected trials and failure recovery, rather than presenting speculative
examples as verified walkthroughs. Do not start implementation until this
written design and the subsequent implementation plan are reviewed.
